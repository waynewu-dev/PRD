二、产品定位与设计原则

2.1 产品定位

不是"又一个ATS"，而是招聘团队的AI协作层。用WorkBuddy的AI能力做决策和执行，企业微信智能表格做数据持久化，企微连接器做通知触达。

2.2 核心设计原则

原则含义
AI是第一公民AI不是"功能按钮"，而是流程引擎。简历进来AI直接给判断和理由
体验双向优先兼顾HR操作效率和候选人体验，不偏废
数据外挂，AI决策WorkBuddy负责思考，数据库负责记录，各司其职
流程闭环从需求提报到入职，不出现手工交接断点
渐进式智能化先跑通核心流程，再叠加AI和数据深度能力

2.3 与传统ATS的本质差异

维度传统ATS（如Moka）基于WorkBuddy的招聘系统
AI角色功能插件流程引擎（第一公民）
操作方式点按钮、填表单对话式（自然语言）
定制化配置项有限Skill封装SOP，无限深度
自动化固定规则工作流Automation定时任务，灵活组合
多角色统一界面+权限Expert包按角色分发能力
数据存储自建数据库企业微信智能表格
上线速度月级周级（MVP）
生态打通需额外对接企微通讯录/审批/日程/消息原生打通

3.4 部署架构：云端 + 本地协同

Core Insight

云端 WorkBuddy 企业版是生产环境（7x24运行，Automation定时任务，Skill统一版本，多HR共享）；本地 WorkBuddy 是管理后台（仅管理员用于创建Agent、配置Skill、调试发布）。HR和面试官不需要安装本地 WorkBuddy——通过企微 AIBot 或 Web URL 即可使用。

5.4 权限设计（两层独立体系）

第一层：用户文档权限（HR个人） ├── HR专员 → 「仅浏览」→ 打开表格只能看，点不动 ├── HR主管 → 「可编辑」→ 保留应急手动操作通道 └── 招聘总监 → 「可管理」→ 可修改表结构 第二层：应用API权限（WorkBuddy） └── 企业微信自建应用 → 拥有智能表格读写API权限 └── 通过应用身份（corpid + corpsecret）调用 └── 与HR个人的「仅浏览」权限完全独立，互不干扰 效果： HR打开表格 → 只能看，改不了 HR对WorkBuddy说"帮我约张三面试" → WorkBuddy用自己的应用权限写入 → 成功 ✅

六、多HR协同方案

6.1 协同模型：Owner绑定

核心原则：一个候选人一个Owner，其他HR只读+评论。这和真实招聘团队的工作模式完全一致。
协同权限模型 ├── Owner（负责人）：读 + 写 + 状态变更 + Offer操作 ├── Viewer（协作者）：读 + 评论/备注 └── Admin（招聘主管）：全部权限 + 转交 + 覆盖（有操作日志）

6.2 三道防线防并发冲突

防线层级机制
第一道：Owner绑定流程设计（治本）候选人入库自动分配Owner，只有Owner可修改状态
第二道：AI中间层守卫技术防护WorkBuddy写入前校验Owner身份，拦截越权操作
第三道：版本检查程序兜底写入前比对updated_at，发现变更则放弃写入并通知
实际场景举例

HR B 对不属于自己的候选人发起操作时：

HR B："帮我淘汰张三"

WorkBuddy AI检查 → 读取Owner字段 → 发现Owner是A → 拒绝操作

回复："张三当前由A HR负责，你无法直接操作。如果需要建议淘汰，我可以帮你在备注里留言说明理由。"

八、性能与扩展策略

8.1 企业微信智能表格性能基准

指标数值评估
单表行数上限10万行5年不清理也不会触达
单表列数上限150列实际使用约70列，充裕
单元格总数上限1500万个等价10万行×150列
批量写入上限500条/次API批量操作
写入并发建议串行，0.2-0.5s/次HR无感知
附件大小上限200MB/个简历PDF通常<5MB

8.2 三种规模的应对方案

候选人规模方案性能
<2000（日常活跃）单表直接存，无需优化秒级，无感
2000-10000（含历史）冷热分离，活跃表+归档表活跃表秒级
>10000（多年累积）按年归档 + 汇总看板始终保持流畅

8.3 性能优化要点

• 避免在热数据表上使用大量公式字段，计算逻辑放在WorkBuddy AI侧

• 汇总看板用Automation定时生成，不做实时聚合查询

• 归档表按年分智能表格文件，避免单表过大

• API写入串行策略：招聘场景操作频率低（50-200次/天），远低于企微API阈值

十一、风险与应对

风险等级应对措施
企微智能表格行数接近上限低按季度归档+按年分表，可撑5年以上
企微API写入串行瓶颈低单次0.2-0.5秒，HR操作频率远低此值
Owner绑定后人力不足中支持批量转交+自动负载均衡分配
WorkBuddy AI误判导致错误操作中关键操作（发Offer、淘汰）需二次确认
候选人隐私数据合规中字段级权限控制+定期清理+满足个保法
企微智能表格服务不可用低SLA 99.9%+核心数据定期导出备份
WorkBuddy平台演进方向变化中三层解耦，AI层可迁移，数据层独立
